# Technical Review

검토 기준일: 2026-07-17

## 프로젝트 요약

- 유형: 모바일 2D 슈팅 로그라이트(뱀서라이크)
- 개발 기간: 4주
- 엔진: Unity `6000.0.34f1`
- 주요 기술: C#, Unity 2D, URP, UGUI, Coroutine, Object Pool, UnityWebRequest
- 외부 구성: Node.js·MySQL 기반 로그인, 회원가입, 랭킹 API와 연동된 클라이언트 코드
- 규모: 자체 게임 스크립트 56개, 약 3,165줄
- 핵심 구현: 자동 전투, 다중 무기, 적 스폰, 웨이브, 레벨업 특전, 드롭, 풀링, UI와 결과 흐름

## 현재 상태

- `Main_SurvLike`, `Game_SurvLike`, `Result_SurvLike` 3개 씬이 빌드 설정에 활성화되어 있다.
- YouTube 시연 영상과 게임 화면·시스템 설명을 담은 21쪽 PDF가 있다.
- 프로젝트용 Edit Mode/Play Mode 자동화 테스트는 없다.
- 정확한 Unity 버전에서의 현재 실행 검증은 완료되지 않았다.

현재 PC에는 Unity `6000.4.0f1`만 설치되어 있고 요구 버전인 `6000.0.34f1`은 없다. 생성된 `Assembly-CSharp.csproj`의 MSBuild 검증은 요구 버전 경로의 Unity Source Generator를 찾지 못해 컴파일 이전 단계에서 실패했다. 따라서 이 결과는 코드 컴파일 실패를 의미하지 않으며 정상 빌드도 보증하지 않는다.

## 잘 보여줄 만한 점

- 이동, 전투, 성장, 웨이브, 게임 종료까지 완결된 루프를 구현했다.
- 다수 개체가 등장하는 장르 특성을 고려해 적, 투사체와 드롭에 풀링을 적용했다.
- 탄막, 회전, 투척, 근접 범위, 주기적 폭발처럼 서로 다른 무기 동작을 구현했다.
- `IDamageable`, `IDroppable`, `IMagnetic` 인터페이스로 일부 행동 경계를 표현했다.
- UnityWebRequest와 JSON을 이용해 로그인·회원가입·랭킹 클라이언트를 연결했다.

## 아쉬운 점과 구조적 부채

- 특전, 스탯, 확률, 상한, 웨이브와 리소스 경로가 코드에 하드코딩되어 있다.
- `ObjectManager.Spawn<T>`와 `PoolManager.GetObject<T>`가 타입 조건문에 의존한다.
- 전역 싱글톤, 정적 이벤트, 오브젝트 이름 검색과 `Resources` 경로 의존이 강하다.
- 자석 효과와 폭발은 컬렉션 전체를 순회하지만 실제 비용을 측정한 자료가 없다.
- 실행 절차와 테스트 결과가 저장소에 누적되어 있지 않았다.
- 자체 코드보다 외부 에셋과 데모 리소스의 저장소 비중이 매우 크다.

## 공개 리스크

- Git 추적 파일은 약 13,342개, 총 약 449MB이다.
- 외부 에셋 팩의 원본 이미지, 음원, 편집 파일과 데모 씬이 다수 포함되어 있다.
- 일부 개별 라이선스 파일은 있으나 저장소 전체의 출처 목록은 없다.
- 루트 MIT 라이선스를 외부 에셋까지 적용되는 것으로 오해하지 않도록 분리 표기가 필요하다.
- 현재 및 이전 랭킹 서버 주소가 `RankMain.cs`에 기록되어 있다.
- 하드코딩된 API 키나 토큰은 이번 정적 검색에서 발견되지 않았다.

공개 전 실제 사용 에셋, 출처, 라이선스, 수정 여부와 재배포 가능 여부를 확인하고 불필요한 원본·데모 파일을 제거해야 한다.

## 면접에서 강조할 포인트

- 짧은 기간에 완결된 게임 루프를 구성하고 우선순위를 조정한 과정
- 다수 개체 장르에서 풀링을 도입한 이유와 이후 측정 기반 개선 결과
- 무기별 공격 모델과 공통 피해 처리 흐름
- UnityWebRequest·JSON 기반 서버 연동과 장애 처리 개선
- 과거 하드코딩 구조를 데이터 기반으로 전환한 단계별 과정

## 면접에서 방어해야 할 포인트

- 싱글톤과 정적 이벤트가 많은 이유 및 씬 전환 수명주기 문제
- `Resources`와 오브젝트 이름 검색을 사용한 당시 판단
- 자동화 테스트와 측정 결과가 없었던 이유
- 외부 에셋의 사용 범위와 라이선스 관리 방식
- 로그인 서버가 없을 때 게임 실행이 제한될 수 있는 구조

## 권장 작업 순서

1. 정확한 Unity 버전에서 메인·게임·결과 흐름을 재현한다.
2. 알려진 풀링, 거리, 코루틴과 이벤트 오류를 작은 단위로 수정한다.
3. 라이선스 목록과 공개 범위를 정리한다.
4. Excel 원본과 C# 검증 컨버터의 특전 수직 구현을 만든 뒤 드롭 → 적·무기 → 웨이브 순서로 확장한다.
5. 100·300·500개체 조건에서 수정 전후 성능을 기록한다.

구체적인 상태와 완료 조건은 `docs/ROADMAP.md`에서 관리한다.
