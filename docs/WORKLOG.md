## 2026-07-17 — 최초 기술 검토

### 수행 내용

- 포트폴리오 20점 평가 기준과 C# 프로젝트 정리 규칙을 적용했다.
- README, Unity 버전, 패키지, 빌드 씬, 소개서와 핵심 스크립트를 확인했다.
- 자체 게임 스크립트 56개, 약 3,165줄을 기준으로 주요 구조를 검토했다.
- Git 추적 파일 약 13,342개, 약 449MB를 확인했다.
- 풀링, 코루틴, 이벤트, 서버 연동과 외부 에셋 공개 위험을 검토했다.

### 검증 결과

- 요구 Unity 버전: `6000.0.34f1`
- 설치 Unity 버전: `6000.4.0f1`
- 빌드 씬 3개가 Editor Build Settings에 등록되어 있다.
- 프로젝트용 자동화 테스트는 발견되지 않았다.
- C# 소스를 UTF-8로 읽었을 때 명확한 대체 문자(`�`)는 발견되지 않았다. 실제 UI 문자열은 에디터 실행 시 재확인이 필요하다.

### 빌드 시도

```text
MSBuild Assembly-CSharp.csproj /t:Build
```

결과: 실패. 생성된 프로젝트 파일이 설치되지 않은 Unity `6000.0.34f1`의 Source Generator DLL을 참조했다. 코드 컴파일 결과로 간주하지 않는다.

### 판정

- 판정: 개선 후 사용
- 추천 위치: 데이터 설계와 성능 최적화를 보여주는 보조 포트폴리오

## 2026-07-17 — 문서 운영 체계 구축

### 목표

다른 Codex 채팅이나 작업자가 참여해도 동일한 우선순위와 기록 방식을 유지한다.

### 변경 내용

- `README.md`: 프로젝트 소개, 구조, 실행법, 현재 검증 상태와 문서 링크를 추가했다.
- `PROJECT_GUIDE.md`: 장기 목적과 범위 제한 중심으로 정리했다.
- `AGENTS.md`: 모든 작업자가 따라야 할 문서 확인, 상태 변경, 검증 및 기록 규칙을 추가했다.
- `docs/TECHNICAL_REVIEW.md`: 최초 평가와 위험 기준선을 작성했다.
- `docs/ROADMAP.md`: P0~P4 작업, 상태와 완료 조건을 작성했다.
- `docs/WORKLOG.md`: 날짜별 작업과 검증 결과를 누적하는 문서를 만들었다.

### 검증

- 문서 간 역할을 분리하고 작업 상태의 단일 기준을 `docs/ROADMAP.md`로 지정했다.
- 현재 `진행 중`인 Roadmap 항목은 없다.
- 다음 추천 작업은 `P0-01` 정확한 Unity 버전에서 실행 기준선 확보이다.

### 남은 사항

- 새 문서와 기존 `PROJECT_GUIDE.md`는 아직 Git에 스테이징하거나 커밋하지 않았다.
- 정확한 Unity 버전에서의 실행 및 스모크 테스트는 아직 수행하지 않았다.

## 2026-07-17 — Excel 기반 데이터 파이프라인 결정

### 결정

- Excel 파일을 밸런스와 콘텐츠 데이터의 원본으로 사용한다.
- C# CLI 컨버터가 스키마와 데이터 참조를 검증한 뒤 Unity용 데이터를 생성한다.
- 생성 결과는 직접 편집하지 않으며 동일 입력에서 동일 결과가 생성되도록 한다.
- 첫 구현 범위는 특전 데이터 하나의 Excel → 검증 → 생성 → Unity 로딩 전체 흐름이다.
- 파이프라인이 안정화되기 전에는 별도 데이터 저장소와 Git 서브모듈을 도입하지 않는다.

### Roadmap 반영

- 기존 P2의 단순 ScriptableObject 전환 계획을 Excel 데이터 파이프라인 구축 단계로 교체했다.
- 공통 스키마, 검증기, 결정적 생성, 데이터별 전환, CI 검사와 서브모듈 재평가를 독립 항목으로 분리했다.

### 이유

- 실무에서 사용한 데이터 운영 경험을 개인 프로젝트에 재현할 수 있다.
- 대량 밸런스 데이터를 표 형태로 편집하면서 코드와 콘텐츠 변경을 분리할 수 있다.
- 중복 ID, 잘못된 참조와 범위를 Unity 실행 전에 차단하는 과정을 포트폴리오로 설명할 수 있다.
- 현재 개인 프로젝트 규모에서는 데이터 저장소 분리보다 컨버터와 검증 체계 완성이 우선이다.

## 2026-07-20 — Unity 6000.3.20f1 업그레이드 검증

### 변경 이유

- 기존 요구 버전 `6000.0.34f1`에 알려진 보안 취약점 경고가 있어 Unity `6000.3.20f1`로 업그레이드했다.
- 이후 작업의 실행 기준선을 지원되는 LTS 버전으로 고정한다.

### 자동 변경 범위

- `ProjectSettings/ProjectVersion.txt`의 에디터 버전이 `6000.3.20f1`로 변경됐다.
- 2D, Input System, URP, Shader Graph와 VFX 패키지 및 잠금 파일이 Unity 6.3 호환 버전으로 갱신됐다.
- URP 전역 설정, 그래픽 설정, 플랫폼 최소 버전, 머티리얼과 SVG 임포터 데이터가 새 직렬화 형식으로 마이그레이션됐다.
- 씬, 프리팹과 자체 C# 소스에는 업그레이드로 인한 변경이 발생하지 않았다.

### 검증 결과

- Editor 로그에서 C# 컴파일 오류와 셰이더 오류가 확인되지 않았다.
- 사용자가 `Game_SurvLike`에서 전투, 레벨업 특전, 게임오버와 결과 화면 진입을 수동 확인했다.
- 사용자가 주요 UI와 이펙트에서 깨진 부분이 없음을 확인했다.
- 사용자가 플레이어 빌드를 생성하고 실행되는 것을 확인했다. 빌드 타깃과 세부 설정은 기록되지 않았다.
- `Main_SurvLike`의 로그인과 회원가입 요청은 `survivalgame.xyz` DNS 해석 실패(`Curl error 6`)로 진행되지 않았다.

### 판정과 남은 사항

- 로그인 실패는 Unity 버전 업그레이드가 아니라 기존 외부 서버 의존 문제로 분리한다.
- `P0-01` Unity 업그레이드와 실행 기준선 확보를 완료 처리한다.
- 메인부터 결과까지의 전체 스모크 테스트를 위해 `P0-04` 서버 미사용 시 실행 정책과 게스트/오프라인 진입 경로를 다음 작업으로 권장한다.
- 자동화 테스트와 빌드 타깃별 검증은 아직 없다.
